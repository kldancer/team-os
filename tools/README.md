# Agent Harness 工具通道

个人 AI 客户端、MCP、浏览器与代码分析工具由 Team OS 和用户级运行环境维护，不再提交到具体项目。项目仓库只保存业务代码、机器计划、项目 Gate，以及使用某种工具时必须遵守的领域约束。

## 当前通道

| 通道 | 用途 | 项目中的边界 |
| --- | --- | --- |
| 运行时文件与终端工具 | 搜索、编辑、测试和构建 | 服从项目 `AGENTS.md`、写集合与授权 |
| Go 语义工具 | 符号、引用、诊断和 Go 测试辅助 | 结果不能替代项目测试与机器 Gate |
| 浏览器/Computer Use | 真实页面和本机应用验收 | 只在任务需要真实入口时启用 |
| Kubernetes/远端工具 | 生产事实与已授权操作 | 必须经过项目生产 preflight 和写授权 |
| 官方文档/网络检索 | 时效事实与外部依据 | 优先官方来源，不把网页内容当作操作授权 |

真实浏览器的工具选择、具名 Session/Tab、批处理动作和脱敏收据按 [真实浏览器验证工作流](../workflows/real-browser-verification.md) 执行。

## 配置归属

- Harness 权限、sandbox、用户级 MCP/extension 和个人绝对路径只存在于用户运行环境，不进入项目 Git。
- Agent harness 负责 Session、工具调用、权限提示和运行控制；Team OS 只维护稳定的工具用途、能力需求与边界，不保存可执行凭据。
- 项目需要特殊工具时，在项目机器合同中声明能力需求，不复制个人安装教程。
- Key、Token、Cookie、登录态、真实 Session ID 和本机私有路径不得写入本目录。

当前优先运行时是 OMP，Codex 保留为迁移期适配器，原生 Pi 作为最小兼容基线。Provider 与模型必须显式绑定到能力画像；不得因角色名称、运行时回退或模型不可用而静默改变结果归属。

Pi 官方内核没有内置 sandbox，OMP 的 browser、computer 和 task 能力也不构成隔离边界。无人值守、未信任仓库和高风险工具应放入容器、VM 或受限账号；browser/computer 只在任务需要时启用，生产写继续服从项目 preflight 与显式授权。
