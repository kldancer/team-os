# 通用协作评测

本目录保存少量冻结任务、评分准则和脱敏结果，用于比较工作流变化是否真正改善质量和效率。TOS0.5 先定义评测合同和案例模板；建立真实 cohort 前不宣称任何多 Agent 或跨模型策略优于 GPT-5.6 单 Agent 基线。

至少评估：

- 结果正确性与验收覆盖；
- 发现缺陷、回归和风险的能力；
- 总耗时、人工干预次数和阻塞时间；
- Token、重复读取和无效 Agent 启动成本；
- 交接完整性与权威引用准确性；
- 端到端价值切片、交接次数/等待、逃逸缺陷和回退准备；
- 变更范围、可回退性和敏感信息安全。

同一冻结任务应比较强单 Agent、必要的多角色协作和不同上下文策略。每个新增 Agent 还必须记录最终采用的独有证据；只重复共同结论的 Agent 计为协调成本。

首个 cohort 使用 8～12 个脱敏冻结案例，至少覆盖研究/写作、局部实现、诊断、跨边界设计和高风险只读决策。先比较成功、严重遗漏和不可逆残留，再比较首次判别事实、总耗时、返工、用户纠偏、Token、重复读取与交接损失。

软件案例至少比较“一个端到端 Feature Owner 按需加载能力”和“前端/后端/UI 固定拆分”两种策略。专业拆分只有在质量、严重遗漏或总周期上稳定胜出，并且没有把集成成本转移给 Michael 或用户时才晋升；单纯增加并行量、代码量或 Agent 活跃度不算收益。

规则晋升门槛：质量不下降且总成本更低；或成本增加但严重遗漏/高风险错误显著减少。小样本只决定下一轮候选，不宣称普遍优越。模型升级、提示词、拓扑和工具集每轮只改变一个主要变量。

案例结构见 [`../templates/eval-case.yaml`](../templates/eval-case.yaml)。原始运行数据进入忽略的 `.work/evals/`，本目录只保留脱敏案例、rubric 和经多轮验证的结论。
