# 通用协作评测

本目录保存可选的脱敏案例、观察维度和长期结论，用于在真实使用中持续发现质量、效率和协作成本问题。它不是实施前置 Gate，也不要求先运行短期 A/B cohort；用户的长期体验、返工与实际结果是主要反馈来源。

至少评估：

- 结果正确性与验收覆盖；
- 发现缺陷、回归和风险的能力；
- 总耗时、人工干预次数和阻塞时间；
- Token、重复读取和无效 Agent 启动成本；
- 交接完整性与权威引用准确性；
- 端到端价值切片、交接次数/等待、逃逸缺陷和生产恢复准备；
- 变更范围、长期维护性和敏感信息安全。

当某类问题反复出现时，可以用相近真实任务或脱敏样例比较单 Agent、多角色协作和不同上下文策略。每个新增 Agent 仍应贡献最终采用的独有证据；只重复共同结论的 Agent 计为协调成本。

不规定首个 cohort、样本数量或完成日期。观察在日常任务中按需积累，先看结果失败、严重遗漏和越权，再看首次判别事实、总耗时、返工、用户纠偏、Token、重复读取与交接损失。

软件案例至少比较“一个端到端 Feature Owner 按需加载能力”和“前端/后端/UI 固定拆分”两种策略。专业拆分只有在质量、严重遗漏或总周期上稳定胜出，并且没有把集成成本转移给主会话或用户时才晋升；单纯增加并行量、代码量或 Agent 活跃度不算收益。

规则调整以长期实际收益和用户判断为准：质量与完成度优先，随后减少返工、等待、无效上下文和协调成本。一次异常不自动扩写永久流程；调整后继续在真实任务中观察和修正。

需要结构化复盘时可使用 [`../templates/eval-case.yaml`](../templates/eval-case.yaml)。项目已有机器任务状态时，优先把结果、首次判别事实、返工、用户纠偏和交接次数附在原任务关闭记录中，避免另建重复账本；只有跨任务分析确实需要原始样本时才写忽略的 `.work/evals/`。本目录只保留脱敏案例、观察准则和长期结论。
