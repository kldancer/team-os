# 模型组合与准入策略

## 当前运行基线

个人工作流只依赖 Codex 原生客户端。当前用户选择 GPT-6 Astra 负责复杂结果与最终综合；既有 GPT-5.6 Sol、Terra、Luna 保留为显式可选层，不自动修改已有任务的模型。模型不能因角色名称自动切换，也不得静默换 Provider；主模型升级不意味着每个协作任务都需要同档模型。

Team OS 不安装其他 CLI、不保存 API Key，也不实现模型路由。`catalog.yaml` 只是研究候选清单，不是运行配置。

## Astra 下的指令设计

采用短内核、按意图触发 Skill 和按需证据：保留安全边界、用户结果与不可弱化的验收，删除固定假设数量、无意义复述和执行器结束即停止任务的歧义。已授权的可逆工作连续推进；普通失败在同一结果内修复，依赖用户决策的分支才等待。不通过堆叠角色、全量测试或更长 Prompt 来证明认真。

此取舍参考 [OpenAI 当前模型指导](https://developers.openai.com/api/docs/guides/latest-model) 对 Astra 指令遵循、澄清倾向和验证行为的说明，以及 [Skill 编写指导](https://learn.chatgpt.com/docs/build-skills) 的触发清晰、按需加载原则。它是工作流设计取舍，不是模型性能保证；实际收益按 `evals/README.md` 在真实使用中验证。

## 新模型准入

新增模型必须同时闭合：

1. **独有证据**：在真实任务中产生当前主模型基线没有提供、且最终被采用的证据；
2. **运行合同**：启动、工具、Session 恢复、停止、失败和超时语义可验证；
3. **数据治理**：密钥只在运行时注入，数据边界、价格、模型漂移和降级可解释；
4. **用户体验**：不迫使用户离开主要 Codex 工作形态，也不增加常规任务步骤。

排名、自报 benchmark、上下文窗口和“另一模型也同意”都不能替代上述证据。Claude 系列按用户要求排除。

## 可选证据通道

Gemini、DeepSeek、Grok、Kimi 和 Qwen 的既有研究结论保留在 `catalog.yaml`。在 Codex 原生集成与真实准入 Gate 闭合前，它们都不是默认角色、回退路径或项目依赖。需要时优先把它们限制为隔离、只读、可丢弃的研究试点，再比较独有证据、错误相关性、Token、延迟和人工纠偏。
