# 模型组合与准入策略

## 当前运行基线

个人工作流只依赖 Codex 原生客户端和 OpenAI GPT-5.6 系列：Sol 负责复杂结果与最终综合；Terra、Luna 只有在用户明确选择或真实任务证明质量/吞吐收益时才使用。模型不能因角色名称自动切换，也不得静默换 Provider。

Team OS 不安装其他 CLI、不保存 API Key，也不实现模型路由。`catalog.yaml` 只是研究候选清单，不是运行配置。

## 新模型准入

新增模型必须同时闭合：

1. **独有证据**：在真实任务中产生 GPT-5.6 基线没有提供、且最终被采用的证据；
2. **运行合同**：启动、工具、Session 恢复、停止、失败和超时语义可验证；
3. **数据治理**：密钥只在运行时注入，数据边界、价格、模型漂移和降级可解释；
4. **用户体验**：不迫使用户离开主要 Codex 工作形态，也不增加常规任务步骤。

排名、自报 benchmark、上下文窗口和“另一模型也同意”都不能替代上述证据。Claude 系列按用户要求排除。

## 可选证据通道

Gemini、DeepSeek、Grok、Kimi 和 Qwen 的既有研究结论保留在 `catalog.yaml`。在 Codex 原生集成与真实准入 Gate 闭合前，它们都不是默认角色、回退路径或项目依赖。需要时优先把它们限制为隔离、只读、可丢弃的研究试点，再比较独有证据、错误相关性、Token、延迟和人工纠偏。
