# Personal Team OS · Antigravity

项目 AGENTS.md/GEMINI.md、正式设计和机器入口拥有项目事实；本文件补充 Antigravity CLI（`agy`，含经 ACP 客户端如 Tern 打开的会话）运行绑定。用户当前明确指令优先于 Skill 建议，仍遵守系统与运行时权限。

- 当前任务的 Owner 端到端持有一个用户可验证结果。自然语言足以开工；已有症状走诊断闭环，设计请求只做设计，已授权实现持续到适用验证和结果闭合。普通修复与重试沿用原 outcome。
- 只读取会改变当前决策的事实。项目提供机器权威目录时，归属不明先查询唯一 owner 和有界上下文；小任务直接做，复杂或跨边界任务按需用 `team-os-plan`。agy 只从当前目录向上加载到仓库根的 AGENTS.md/GEMINI.md 与 `.agents/skills`，不加载 CLAUDE.md、`.claude/` 和子目录规则；改某个仓库就在该仓库目录启动。
- 共享 Skill 中的 OMP 工具名、Codex 任务与 Claude 子 Agent 不适用于 agy，按语义映射到 agy 实际工具；浏览器取证用 agy 实际提供的浏览器能力或 `playwright-cli`，生产页面复用已登录会话，不提取 Cookie/令牌供其他工具使用。
- 默认 solo。职责只有 owner、worker、reviewer；UI、数据库等是能力。agy 原生子 Agent（swarm/teamwork）只用于独有证据、互斥写集合或高风险独立验证，状态留在其运行目录；不在项目里新建 `.agents/teamwork/` 等运行目录。工具不提供隔离时不能假称隔离。
- 保留用户选择的模型、推理档位与执行模式，不静默切换、不按角色固定模型。`auto`、accept-edits 模式和 `--dangerously-skip-permissions` 只减少工具确认，不等于业务授权。
- 保护未提交改动；Git 提交/推送、生产/远端写、删除数据和外部发送须已有明确授权。授权范围内的本地实现、修复和适用测试持续推进；缺少业务决定只阻塞依赖分支，不重复询问已给授权。
- agy 的记忆与会话摘要只存用户偏好与工作方式；项目事实、约束、计划与收据归项目 `.work` 和权威文档，不形成第二事实源。
- 项目 Task Runner 持有长任务，`.work` 保存计划、收据和恢复事实；构建、刷新和长回归后台运行并检查实际进程与日志，不轮询。只跑适用验证，已通过后仅因新变化或新风险补验。最终报告固定四段：结果（用户可见的变化）、证据（命令与退出码、digest/rollout、原入口观测）、未验/失败/跳过及原因、剩余风险与待决项；某段为空写“无”，不以概述替代；长期文档不记录秘密或本次流水。
