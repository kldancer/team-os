# 上下文经济与派工包

一个事实只让一个模型读一次。分析、决策和最终综合属于保留角色；原始探索、批量读取和执行属于默认模型。本文件是读取纪律、派工包、证据包和上下文记账的唯一权威；项目只补充自己的命令、路径、Gate 入口和证据目录。

## 1. 读取纪律

对所有角色生效，包括保留的分析角色：

- 目标已知时直读目标片段，不从入口文档遍历；使用带区间的读取选择器，不整份 `:raw`；派工包已给区间时首次读取就用区间，不得先整份读再补区间。
- 先取结构摘要，再只补缺失区间；超过约 20KB 的文件默认不整份 raw 读取。
- 符号级导航用 LSP（definition / references / hover / type_definition），不用全文搜索替代。
- 机器事实用项目脚本查询（计划、收据、任务状态、配置、profiles），不 raw 读 60KB 级的 JSON/YAML 清单。
- 同一输入、同代次已被本任务读取或验证过，不重复读取、不重复运行；引用收据引用键与命令实例。
- 已写进派工包或证据包的结论，不再要求下游重读原始正文。
- 探索是证据采集：为回答一个判别问题而读，得到答案即停，不扩展为全仓审计。

## 2. 派工包

任何需要下游动手或取证的任务，先由负责人写一份自足的派工包，再派发。派工包是下游唯一入口，下游不再从设计文档或规划正文反推意图。

必填字段：

| 字段 | 内容 |
| --- | --- |
| 身份 | 任务 ID、仓库 key、仓库绝对路径、工作目录 |
| 写集合 | 允许写入的绝对路径或 glob；禁止写入的路径 |
| 读集合 | 允许读取的路径或范围 |
| 禁止读取 | 已蒸馏进本包的文档/路径，避免重复读取 |
| 变更 | 按顺序的步骤：文件 + 符号 + 行锚点 |
| 合同 | 必须遵守的接口签名、字段、状态与错误语义（内联，不引用外部正文） |
| 验收 | 精确命令与预期结果；需要交付的收据 |
| 停止 | 何时停止并回报，而不是自行决策 |
| 输出 | 实际改动路径、行为变化、验证结果、剩余风险 |

规则：

- 路径必须来自项目机器注册表（如 `workspaces.json`），下游不得自行发现仓库位置。
- 下游确需原文时，引用文档的具体章节，不引用整份文档。
- 合同不完整、路径与现有改动重叠或需要跨边界决策时，下游停止并回报，不自行扩大范围。
- 派工包写入任务证据目录（如 `.work/tasks/<task>/worker-pack.md`）或 `local://`，随任务保留，后续波次复用。

模板见 [`../templates/worker-pack.md`](../templates/worker-pack.md)。

## 3. 证据包

保留角色需要原始探索时，交给快速只读角色，取回带文件/行锚点的压缩证据包；保留角色只读压缩包并抽查关键断言，不自行全量读源码或文档。

证据包必须：区分事实、推断与未知；给出精确路径/行号或来源；说明证明了什么、还缺什么、最小下一步是什么。证据包不替代负责人的判断，也不作为写入授权。

## 4. 执行模型与角色保留

- **保留（显式绑定）**：结果合同与规划、跨边界设计与状态冻结、深度评审与视觉设计、最终综合。这些角色必须显式绑定，不随会话默认漂移。
- **执行档（显式绑定）**：侦察、批量取证、有界实现、门禁/冒烟/刷新/生产事实等叶子执行、收据写入、机械文档更新。执行档必须由 `@fast_worker` 和泛型 worker 的模型覆盖（如 `task.agentModelOverrides`）落实，不能依赖会话默认模型——未绑定的子角色会继承父 Session 模型。
- **末端或机械车道**：提交、推送、机械改文档、查询收据不需要额外角色绑定，由当前会话或默认模型直接执行，不为此新建角色或会话。
- 执行角色的写入仍由负责人复核真实 diff 与集成入口；复核以收据摘要、diff 统计和定点读取为主，不重读改动文件全文。
- 模型不得静默改变负责人：绑定缺失、回退到非预期 Provider 或实际模型与绑定不一致时，停止执行并披露。

## 5. 记账

上下文与成本按机器事实记录，不手工填报：

- 结果关闭时记录已知的首次判别事实耗时、返工、用户纠偏与交接次数；缺失值为 null，不猜零。
- 模型 token、缓存读取、工具结果体积、重复读取和每模型/每 agent 类型占比，由运行时统计库按窗口汇总。
- 执行与复用分开计数；命令耗时不是人工工时；通过率不是业务质量。
- 用测量结果决定扩大或收回某类角色的工作量，而不是用印象或模型名称。
