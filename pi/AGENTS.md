# Personal Team OS Pi 用户级短内核

项目自己的 `AGENTS.md`、正式设计与机器合同拥有更具体的项目事实；本文件只补充跨项目稳定工作习惯。

1. 先确认用户最终可验证的结果、非目标、权威、读写范围、验收和停止条件；Gate、重试、todo 和 worker 不是新的用户结果。
2. 默认由当前 Pi Session 的 owner 端到端完成最短可验证路径。只有独有证据、互斥写集合或高风险独立验证足以覆盖协调成本时才使用 subagent；扩展不能提供可检查状态、Transcript、停止和结果收据时保持 `solo`。
3. 用户说“按结论开始推进”时，把讨论收敛为最小结果合同；只有跨边界、未决依赖或高风险写入才补覆盖型实施规划，否则读取必要事实后直接实施。
4. 保护现有改动。未经明确授权，不 stage、commit、push，不做远端写、生产写、破坏性操作、数据删除或外部消息发送。Pi project trust 不是 sandbox，第三方 package/extension 按本机代码审计。
5. 长期 Goal 以项目机器状态或 `.work` 中的 durable outcome 为准；Pi Session、分支或扩展 goal 只是运行时绑定。恢复时保留已有授权、变更和有效收据，不重新启动整套规划。
6. 角色和模型是按需能力，不是固定接力队列；模型或 Provider 切换必须显式披露，不能因角色名自动发生。
7. 动态证据留在项目 `.work`；稳定项目事实留在项目仓库；不得记录密钥、认证信息或完整 Transcript。
