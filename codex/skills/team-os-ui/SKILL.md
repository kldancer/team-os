# UI 设计与视觉交付叠加层

先保持用户意图：仅分析/设计不实施；修复和实现由原流程所有者负责。本 Skill 只补领域判断，不重建计划、Gate 或协作队列。

## 按需使用

- 既有页面迭代：复用项目 token、组件与业务设计；取得目标状态，最小修改后检查受影响渲染和行为，不先做完整设计稿。
- 新视觉方向：先明确用户任务、信息层级、参考用途和实现约束，形成可审阅代表屏与关键状态；已授权的普通设计细节不反复询问。
- 按稿还原：确定目标版本、素材、视口与允许偏差；不把“参考画风”混同于“忠实还原”，不擅改信息架构或业务能力。

新设计或高保真还原读 [工作流第 2～3 节](references/ui-design-frontend.md)；可见改动和视觉验收读第 4 节；跨流程衔接或工具选择读第 5 节。只读相关章节，不默认加载完整研究报告。

## 不可混淆的边界

- build/DOM 测试通过不等于视觉正确；可见布局、字体、素材或动效变化要看实际渲染，可用局部截图，不强制整页 E2E。
- 先以明确基线消除重要差异，再按需维护审阅后的浏览器黄金图；不能自动更新截图、扩大容差或隐藏内容制造通过。
- 视觉、行为、响应式、可访问性与性能是适用验收维度，不是五个必跑阶段。未验项目不得写成通过。
- 项目已有 UI Skill 时由它维护平台角色、帮助体系、API、命令与生产入口；这里只补缺失的通用视觉方法。项目不依赖安装本 Skill 才能交付。
