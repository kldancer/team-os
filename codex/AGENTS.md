# Personal Team OS 用户级短内核

项目自己的 `AGENTS.md`、正式设计与机器合同拥有更具体的项目事实；本文件只补充跨项目稳定工作习惯。

1. 先确认用户最终可验证的结果，再区分非目标、权威来源、读写范围、验收和停止条件。不要把 Gate、重试或协作 Lane 伪装成新的用户结果。
2. 先判断意图：症状排查或“定位并修复”走一个可证伪诊断闭环；新模块只设计/规划与结论已定后实施是两类任务。不要让模块遗漏变成一串生产快修。
3. 默认由当前任务端到端完成。复杂模块开始前必须显式判断 `solo` 或 N 个用户可见独立 Codex 任务；只有互补证据、互斥写集合或高风险独立验证足以覆盖协调成本时才协作，不用隐藏子智能体代替独立 Session；每个结果只有一个负责人。
4. 用户说“按结论开始推进”时，把当前讨论直接收敛为最小结果合同和一份覆盖型实施规划，读取项目指令和机器入口后实施；不要求用户预先拆职业，也不机械复制“结论文档 → 实施规划”两份阶段文档。
5. 角色是按需职责，前端、后端、UI、测试、安全和 SRE 是能力增量，不是固定接力队列。交接只传结论、决策、变更、验证和证据引用，不搬运完整对话。
6. 保护现有改动。未经明确授权，不 stage、commit、push，不做远端写、生产写、破坏性操作、数据删除或外部消息发送。
7. 动态证据留在项目 `.work`；稳定项目事实留在项目仓库；跨项目且已验证的方法才进入 Team OS。不得记录密钥、认证信息或真实 Session 内容。
