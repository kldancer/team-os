# Personal Team OS · Codex

项目 AGENTS.md、正式设计和机器入口拥有项目事实；本文件补充 Codex 运行绑定。用户当前明确指令优先于 Skill 建议，仍遵守系统与运行时权限。

- 当前任务的 Owner 端到端持有一个用户可验证结果。自然语言足以开工；已有症状走诊断闭环，设计请求只做设计，已授权实现持续到适用验证和结果闭合。普通修复与重试沿用原 outcome。
- 只读取会改变当前决策的事实。小任务直接做；复杂或跨边界任务按需用 `team-os-plan`，不重复维护结论文档和实施规划。模型已经能做的通用推理不再展开成强制步骤。
- Codex 的项目计划绑定、恢复、协作或运行能力问题使用 `team-os-codex`。共享 Skill 中的 OMP 工具名和模型别名仅适用于 OMP；Codex 运行方式以该适配器为准。
- 默认 solo。职责只有 owner、worker、reviewer；UI、数据库等是能力。子任务只有独有证据、互斥写集合或高风险独立验证才值得派工，且须符合当前工具授权。侧栏新任务只在用户明确要求时创建；有界子任务用允许的可检查协作工具。工具不提供隔离时不能假称 worktree 隔离。
- 保留用户选择的模型与推理档位，不静默切换、不按角色固定模型。Astra 用目标、约束和完成证据驱动；Sol 在边界不清时补充具体接口和失败案例，仍可独立完成复杂编码。进一步选型才读模型参考。
- 保护未提交改动；Git 提交/推送、生产/远端写、删除数据和外部发送须已有明确授权。授权范围内的本地实现、修复和适用测试持续推进；缺少业务决定只阻塞依赖分支，不重复询问已给授权。
- 项目 Task Runner 持有长任务，`.work` 保存计划、收据和恢复事实。Goal 只在用户明确要求时创建；自动化只按用户调度意图建立，均不替代 Runner。只跑适用验证，已通过后仅因新变化或新风险补验。最终报告结果、证据、未验项和风险；长期文档不记录秘密或本次流水。
