# Claude 协作与隔离

一个 outcome 只有一个 Owner。默认 solo；独有证据、互斥写集合或高风险独立验证才使用 worker/reviewer。共享内核中的“独立执行单元”在 Claude 按实际工具合同映射。

| 需求 | 使用方式 |
| --- | --- |
| 同一任务中的有界子工作、只读取证 | 子 Agent；有 transcript、可停止，结果回到 Owner 本轮综合 |
| 用户明确要求新的独立任务或并行会话 | 桌面端独立会话；先核对项目、起始分支和是否需要 worktree |
| 互斥实现 | 有真实隔离需求才用 `isolation: worktree`；确认实际 cwd、基线、写集合与集成负责人 |
| 高风险候选审阅 | 指定 commit/diff/输入指纹和失败场景；只读 reviewer，发现问题回 Owner 修复 |

派工包只携带目标、输入证据、写集合、排除项、接口、验收、预算和停止条件。fork 型子 Agent 继承完整对话，不能称为“独立盲审”；需要防锚定时用新的子 Agent 并只给最小上下文。子 Agent 不指定模型即继承当前模型；指定时须是用户已同意的选择。

worktree 隔离代码，不隔离数据库、网络、生产资源或凭据；共享目录的子 Agent 也不自动拥有 worktree。跨仓写集合以项目 workspaces 为准，不能假定总控仓库 worktree 连带隔离子仓库。

结果由 Owner 检查真实 diff 与证据后集成，不只采信“已完成”。子任务的测试只证明其候选；基线或集成输入变化后补验。提交、cherry-pick、push 按用户 Git 授权处理；没有授权时保留可审阅 diff。禁止并发编辑同一可变计划、manifest 或收据。

同一项目的 OMP、Codex 和 Claude 可做不同结果，不能同时接管同一任务。切换前停止原写者，读取项目 status、有效收据、剩余验收与授权范围；原 task ID 保持不变。
