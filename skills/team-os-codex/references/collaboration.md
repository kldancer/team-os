# Codex 协作与隔离

一个 outcome 只有一个 Owner。默认 solo；独有证据、互斥写集合或高风险独立验证才使用 worker/reviewer。共享内核中的“独立执行单元”在 Codex 按实际工具合同映射，不要求每个子任务创建侧栏新任务。

| 需求 | 使用方式 |
| --- | --- |
| 同一任务中的有界子工作 | 当前工具允许的可检查 subagent；工具权限未允许主动派工时不派工 |
| 用户明确要求新的独立任务 | App create_thread；先核对项目、起始分支和 local/worktree，创建后等待结果 |
| 互斥实现 | 有真实隔离需求才建 worktree；确认实际 cwd、基线、写集合与集成负责人 |
| 高风险候选审阅 | 指定 commit/diff/输入指纹和失败场景；只读 reviewer，发现问题回 Owner 修复 |

派工包只携带目标、输入证据、写集合、排除项、接口、验收、预算和停止条件。若工具继承完整历史，就不能称为“独立盲审”；需要防锚定时给独立最小上下文。

worktree 隔离代码，不隔离数据库、网络、生产资源或凭据；共享目录的 subagent 也不自动拥有 worktree。聚算跨仓写集合以项目 workspaces 为准，不能假定总控仓库 worktree 连带隔离子仓库。

结果由 Owner 检查真实 diff 与证据后集成。子任务的测试只证明其候选；基线或集成输入变化后按项目计划补验。提交、cherry-pick、push 按用户 Git 授权处理；没有授权时保留可审阅 diff。禁止并发编辑同一可变计划、manifest 或收据。

同一项目的 OMP 和 Codex 可做不同结果，不能同时接管同一任务。切换前停止原写者，读取项目 status、有效收据、剩余验收与授权范围；原 task ID 保持不变。计划绑定记录不是跨进程锁，资源互斥由项目 Runner/任务合同保证。

Goal 用于用户明确要求的持续结果；调度/监控用用户要求的 App automation，未变化时安静。它们均不能保证 App 退出后本地命令继续运行；长阶段依靠项目 Runner，并检查实际进程与日志。
